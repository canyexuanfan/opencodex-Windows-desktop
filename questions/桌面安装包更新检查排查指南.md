# 桌面安装包更新检查排查指南

## 问题描述

桌面端“检查更新”不能继续沿用 CLI/npm 包更新逻辑。桌面用户安装的是 Windows 安装包，检查更新应面向用户 fork 仓库的 GitHub Releases，并识别可下载的 Windows Setup 资产。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：只把 `src/update/job.ts` 的 Release notes URL 改为 `https://github.com/canyexuanfan/opencodex-Windows-desktop/releases/latest`。这只能改变展示链接，实际版本查询仍然调用 `npm view @bitkyc08/opencodex`，更新执行仍然是 CLI 包安装；桌面端安装包更新检查并没有真正完成。

## 深层问题分析

桌面端存在两套版本语义：

- 后端代理包版本：根目录 `package.json`，例如仪表盘显示的代理版本。
- Electron 安装包版本：`desktop/package.json`，对应 Windows 安装器版本和桌面壳版本。

桌面安装包更新应使用 Electron 安装包版本比较 GitHub Release tag/资产，而不是使用 npm registry 上的 CLI 包版本。

## 下一步排查策略

1. 让 Electron 主进程启动 sidecar 时写入桌面模式和桌面安装包版本环境变量。
2. `/api/update/check` 在桌面模式下请求 fork 仓库 GitHub Releases。
3. 解析最新 release 的 Windows Setup 资产，提供下载入口；找不到资产时明确提示，而不是回退到 npm。
4. CLI/npm 安装场景继续使用原有自更新流程。

## 调试工具

- `rg "OPENCODEX_DESKTOP|api.github.com/repos|OpenCodex-Setup-x64" src desktop gui tests`
- `bun test tests/update-job.test.ts`
- `cd desktop && bun test tests/package-static.test.ts`

## 注意事项

- 不要在用户正在使用 Codex 时自动运行安装包覆盖自身。
- 不要把桌面安装包更新按钮伪装成 CLI 自更新。
- GitHub Release API 失败、缺少 Windows 安装包资产时，必须给用户可理解的状态。
