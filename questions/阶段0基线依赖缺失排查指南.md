# 阶段 0 基线依赖缺失排查指南

## 问题描述

阶段 0 基线命令在干净工作区执行时，根项目与 `gui/` 均没有安装依赖，导致类型检查、GUI lint/build 和大量测试无法加载依赖。

## 已尝试的修复方法及失败原因

- ❌ `bun run typecheck`：退出码 1，`Cannot find type definition file for 'bun-types'`。工作区没有安装根依赖。
- ❌ `bun run test`：退出码 1。除缺少 `zod/v4`、`@bufbuild/protobuf`、React 等依赖外，当前 Bun 1.2.20 的 `Bun.Image` 为 undefined，相关图像测试无法运行。
- ❌ `cd gui && bun run lint`：退出码 1，`eslint` 不存在。GUI 依赖未安装。
- ❌ `cd gui && bun run build`：退出码 1，`tsc` 不存在。GUI 依赖未安装。
- ❌ 首次 `bun install --frozen-lockfile`：命令超过 120 秒被终止；随后检查确认根依赖已落地，未产生受跟踪文件改动。GUI 安装在单独目录完成。
- ❌ 安装依赖后 `bun run typecheck`：退出码 1，现有 `src/adapters/cursor/native-exec-common.ts` 判别联合类型错误，以及 `src/server/index.ts` 的 Buffer/ArrayBuffer 类型错误；未修改产品代码。
- ❌ 安装依赖后 `cd gui && bun test tests`：退出码 1，437 个测试中 430 通过、7 个 Logs 相关测试失败；失败集中在既有日志轮询/状态测试，未修改产品代码。
- ❌ 阶段 5 复跑 `cd gui && bun test tests`：退出码 1，439 个测试中 432 通过、同一组 7 个 Logs 相关测试失败；错误仍为测试使用的 `jest.advanceTimersByTime` 在当前 Bun 测试兼容层中不存在，未修改非相关日志代码。
- ❌ 阶段 6 首次 `bun run package`：electron-builder 拒绝将 Electron 放在运行时 `dependencies`，并在失败构建后发现旧的 `dist/win-unpacked` 可能被下一次 `dist/**/*` 收入 asar；已修正依赖分区、构建输出清理和资源排除规则。
- ❌ 阶段 7 使用自签名证书执行 `signtool verify /pa`：签名本体已存在，但未受信任根导致链验证失败；临时导入 CurrentUser\\Root 后 Windows Authenticode 查询在本机时间戳/链校验阶段超时，随后确认临时根未留存。该限制不影响签名文件生成，但信任链验证需在测试机完成。
- ❌ 阶段 8 复跑 `bun run test`：根类型检查先通过，但完整测试在 180 秒上限内无结果并被终止；仅发现 `scripts/test.ts`/`bun test --isolate` 进程，已按精确命令行停止，未修改生产代码。既有 Bun 测试运行器不稳定限制继续保留。
- ❌ 阶段 8 产物扫描首次发现 `src/AGENTS.md` 被复制到运行资源；已修正资源复制过滤器，重新生成 4259 文件资源、重新构建并重新签名，随后内部路径和私钥扫描通过。
- ❌ 2026-08-01 在无额外授权下将根完整测试上限提高到 420 秒：测试运行器输出大量业务测试通过，但多个测试在清理临时配置目录时收到 `EPERM/EACCES`，CLI 子进程另有 5 秒超时，最终仍以 420 秒超时退出；症状集中于当前 Windows 沙箱的临时目录/子进程权限，不能据此修改生产代码。
- ✅ 安装依赖后 `cd gui && bun run lint`：通过。
- ✅ 安装依赖后 `cd gui && bun run build`：通过；Vite 仅报告 bundle 大小提示。
- ✅ 阶段 6 `bun run package:resources`：使用锁定 root 依赖生成 4260 文件资源清单，包含 GUI、src、生产依赖和 98 MB Bun 1.3.14 runtime；实际扫描未发现 `.git`、questions、reference、todolist 或证书/密钥后缀。
- ✅ 阶段 6 `bun run package`：生成 `OpenCodex-Setup-x64.exe` 与 `OpenCodex-Portable-x64.exe`；Electron-builder 使用 per-user NSIS/asInvoker 配置，app.asar 不再包含 staging 或旧 unpacked 输出，固定 Bun 位于 unpacked resources/opencodex/runtime。
- ❌ `git clone --depth 1 --filter=blob:none https://github.com/electron/packager.git reference/electron-packager`：退出码 128，Windows 环境 OpenSSL `SSL_ERROR_SYSCALL`；已在参考索引中记录，未重复扩张检索范围。
- ✅ `bun run privacy:scan`：通过。
- ✅ `git fsck --connectivity-only`：通过；仅有两个 dangling tree，无连通性错误。

## 深层问题分析

当前终端使用 Bun 1.2.20，而根 `package.json` 锁定的 Bun 依赖为 1.3.14；安装依赖后仍需确认运行器是否满足项目测试对 Bun 图像 API 的要求。缺失依赖属于环境准备问题，不应通过修改产品代码绕过。

## 下一步排查策略

1. 使用根与 GUI 各自的锁文件安装依赖，优先采用 frozen lockfile。
2. 记录 `bun --version`，确认安装结果与锁定版本关系。
3. 重新运行失败的类型检查、测试、lint、build。
4. 若仅因当前 Bun 运行器缺少 `Bun.Image` 仍失败，保留该环境限制并继续不改产品代码。

- 不手改 `gui/dist`。
- 不为基线测试临时替换生产依赖或屏蔽失败测试。
