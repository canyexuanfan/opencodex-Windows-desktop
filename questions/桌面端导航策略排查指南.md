# 桌面端导航策略排查指南

## 问题描述

桌面宿主必须保持单窗口：同源页面的 `window.open` 不应创建新的 Electron 窗口；同时代理动态端口重启后，旧端口的导航策略不能阻止新 Dashboard origin 加载。

## 已尝试的修复方法及失败原因

- 未进行失败重试。初始实现直接在 `setWindowOpenHandler` 中放行同源 loopback URL，并在每次 `loadDashboard` 时重新注册 `will-navigate` 监听器；静态审计发现这会允许同源 popup，且端口切换后旧监听器仍可能 `preventDefault()` 新 origin。

## 深层问题分析

Electron 的 `setWindowOpenHandler` 返回 `allow` 会创建新窗口，不等同于当前窗口内导航。`webContents.on("will-navigate", ...)` 会累积监听器；重复安装策略后，每个旧闭包仍保存旧端口 origin，因此动态端口切换会触发旧策略拦截。

## 修复与验证

- ✅ 2026-08-01：`desktop/src/navigation.ts` 统一拒绝所有 `window.open`，仅对 HTTP/HTTPS 外链调用系统浏览器；导航策略改为单一监听器并提供 `setExpectedOrigin`/`dispose`。
- ✅ 2026-08-01：`desktop/src/main.ts` 只在窗口创建时安装策略，Dashboard 换端口时更新 origin，窗口销毁时移除监听器。
- ✅ 2026-08-01：`cd desktop && bun run typecheck`、`bun run build`、`bun test tests`（16/16，93 assertions）和 `git diff --check` 均通过。
