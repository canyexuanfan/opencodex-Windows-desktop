# 中文空格安装路径排查指南

## 问题描述

桌面端安装器在包含中文和空格的隔离安装路径中进行静默安装、启动和卸载验收时，安装器返回 0，但未观察到隔离配置根下的 `runtime-port.json`/healthz，且卸载后安装文件仍存在。需要确认 `/D=` 参数解析、安装目标实际路径、进程锁定和路径编码影响。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-01：在确认不存在的 `C:\\tmp\\OpenCodex 路径验收 <guid>\\安装 目录 中文` 目录中运行签名安装器 `/S /D=<path>`；安装器返回 0，但 `OPENCODEX_HOME` 隔离根未出现 runtime-port，卸载器返回 0 后 `OpenCodex.exe` 仍存在。尚未确认 NSIS 是否把带空格参数截断，或 app 是否启动到了其他配置根。
- ❌ 2026-08-01：改用完整引号 `/S /LOG="<path>" /D="<中文空格路径>"` 后仍未创建目标目录；检查发现测试同时把 `TEMP/TMP` 指向了包含中文和空格的根目录，NSIS 只留下 `nsh*.tmp\\7z-out` 空目录且没有安装日志。该次不能证明安装目标参数失效，下一次保持临时目录 ASCII，仅让安装目标包含中文/空格。
- ❌ 2026-08-01：将临时目录改为 ASCII、安装目标保留中文/空格后，NSIS 启动脚本在当前沙箱内未返回可捕获结果，命令端 30 秒超时；随后未发现残留 OpenCodex/Un_A 进程，也未能稳定定位新测试根。该尝试仍不足以证明产品路径处理失败，先保留为安装器运行环境限制，避免继续重复无证据的安装/卸载。
- ❌ 2026-08-01：ASCII 目标路径控制组可创建 `OpenCodex.exe`，但相同 `Start-Process` 方式将目标改为 `安装 目录 中文` 时安装器仍返回 0、轮询 30 秒未出现目标文件。该对照缩小了问题范围到 Unicode 目标参数/NSIS 解包路径，而非安装器整体不可用；下一次改用 .NET `ProcessStartInfo.ArgumentList` 保持宽字符参数。
- ❌ 2026-08-01：当前 Windows PowerShell/.NET 运行时的 `ProcessStartInfo.ArgumentList` 属性为 null，无法用该 API 构造宽字符参数；脚本退回无参数启动安装器并超时，随后已按精确安装器路径确认并清理残留进程。该方法不可用，不修改产品代码绕过。
- ❌ 2026-08-01：仅含 ASCII 空格的安装目标对照也出现安装器等待超时，说明此前用 `/D=` 直接指定最终目录的脚本并不能代表用户在安装器目录页选择父目录的真实流程；该尝试已记录并清理精确安装器进程。下一步改为显式启用 NSIS 目录选择页，并验证程序名子目录由安装器自动补齐。
- ❌ 2026-08-01：在全新父目录 `C:\tmp\OpenCodex 安装路径 smoke 20260801` 中执行已签名安装器 `/S /D=<父目录>` 返回 0，但文件（`OpenCodex.exe`、`resources`、卸载器）直接落在父目录，未创建 `OpenCodex` 子目录。根因是 electron-builder 模板的 `StrContains` 只判断完整路径任意位置是否包含 `${APP_FILENAME}`；父目录名自身包含 `OpenCodex` 时误判为已保留程序名目录。该结果证明当前保护逻辑不足，必须改为检查最后一级目录名精确等于 `OpenCodex`，再重打包验证。

## 深层问题分析

当前结果不能直接归因于应用代码：脚本没有打印 NSIS 实际创建目录、安装后进程命令行或卸载器日志；`Start-Process -ArgumentList` 对 `/D=` 中的空格/中文也可能产生参数边界差异。需要先解析实际目录树和安装器日志，再使用明确引号或短路径复验。

## 下一步排查策略

1. 找到本次精确隔离根，列出一级目录和所有 `OpenCodex.exe` 路径。
2. 检查安装后进程命令行、实际 `OPENCODEX_HOME` 和 sidecar 进程，避免把“未在预期目录启动”误判为应用失败。
3. 若目标路径正确，使用 NSIS 推荐的完整引号 `/D="<path>"` 形式重新安装，并在 app/installer/uninstaller 全部退出后复验。
4. 成功后记录安装版启动、healthz、卸载和用户目录保留证据；若仍失败，再检查安装器日志和打包路径处理。

## 调试工具

- `Get-ChildItem -LiteralPath C:\\tmp -Directory`
- `Get-CimInstance Win32_Process`（按精确 `ExecutablePath`/命令行过滤）
- NSIS `/S /D=<absolute-path>` 参数
- 隔离 `OPENCODEX_HOME`、`CODEX_HOME`、`--user-data-dir`

## 注意事项

- 只操作本次随机生成且事前确认不存在的 `C:\\tmp` 隔离根。
- 不删除用户目录或工作区目录；卸载目标必须是本次测试安装器创建的精确路径。
- 失败记录写入后才能进行下一次参数形式复验。
