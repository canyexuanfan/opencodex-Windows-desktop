# 桌面打包临时目录权限排查指南

## 问题描述

在 Windows/Codex 沙箱环境中重新构建 OpenCodex 桌面安装包时，`desktop` 包的 `package:resources` 阶段需要调用 Bun 安装生产依赖并复制资源。如果 Bun 默认临时目录不可访问，会报 `AccessDenied accessing temporary directory. Please set $BUN_TMPDIR or $BUN_INSTALL`，导致安装包没有生成。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：用户安装并重启 Codex 后复核，当前 `18313/healthz` 正常，但 `~/.opencodex/config.json` 的 `port` 仍为 `10100`，安装目录中的 `src/update/job.ts`/`src/update/index.ts` 未包含 `git-v0.58` 的端口迁移函数，说明用户安装的是最终收口前的安装包。随后尝试用当前仓库执行 `cd desktop && bun run package`，在 `package:resources` 阶段因 Bun 报 `AccessDenied accessing temporary directory. Please set $BUN_TMPDIR or $BUN_INSTALL` 失败。该失败与既有 Windows 沙箱临时目录权限问题同类，不是端口迁移业务逻辑失败。

## 深层问题分析

- Bun 在安装依赖或准备资源时会使用默认临时目录；当前沙箱/Windows ACL 组合可能拒绝访问该目录。
- 端口迁移代码已经在仓库 `git-v0.58`，但用户当前安装目录并未包含最终收口代码，所以需要重新打包一个基于当前工作树的安装包。
- 构建安装包本身不应停止、重启或覆盖安装正在运行的 Codex/OpenCodex；只生成产物，后续安装交给用户手动执行。

## 下一步排查策略

1. 使用明确的 `C:\tmp\opencodex-desktop-package-20260802` 作为 `TEMP`/`TMP`/`BUN_TMPDIR`。
2. 如普通沙箱仍拒绝，使用非沙箱权限只执行构建命令。
3. 构建完成后检查安装包名称、哈希、安装目录 staging 中是否包含 `selectRestartPortAfterReclaim`/`selectPostUpdatePort` 等端口迁移函数。

## 调试工具

- `bun run build:gui`
- `cd desktop && bun run package`
- `Select-String -Path desktop/resources/staging/opencodex/src/update/*.ts -Pattern "selectRestartPortAfterReclaim|selectPostUpdatePort"`
- `Get-FileHash desktop/out/OpenCodex-Setup-2.8.0-x64.exe -Algorithm SHA256`

## 注意事项

- 不要自动运行安装包。
- 不要重启 Codex 或停止当前支撑对话的代理。
- 如果只剩安装/重启验证，交还用户手动操作。
