# 桌面预加载脚本格式排查指南

## 问题描述

最新便携版在隔离目录启动时，Electron 43 的 sandbox renderer 日志报告 preload 无法加载：`SyntaxError: Cannot use import statement outside a module`。当前 `desktop/src/preload.ts` 经 NodeNext 编译为 ESM `dist/preload.js`，但 Electron preload 加载器按 CommonJS 脚本执行，导致桌面桥接 API 不可用，并且本次 smoke 未取得 runtime-port.json。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-01：仅重新签名并启动现有便携版，隔离用户目录和 `--no-sandbox` 均无法消除 preload 语法错误；日志明确指向 `resources/app.asar/dist/preload.js` 的 ESM import。
- ❌ 2026-08-01：首次将源文件改为 `preload.cts` 后直接执行 `bun run build`，现有 `tsconfig.json` 的 include 只匹配 `src/**/*.ts`，未编译 `.cts`；输出目录仍残留旧的 `preload.js`，说明修复还不完整。

## 深层问题分析

桌面主进程可以使用 package.json 的 `type: module` 和 ESM 输出，但 Electron sandbox preload 的执行上下文不是 Node ESM 模块加载器。必须让 preload 产物使用 `.cjs` 扩展名并由 TypeScript 输出 CommonJS，同时主进程引用路径必须与打包后的文件名一致。

## 下一步排查策略

1. 将 preload 源文件改为 `.cts`，让 NodeNext 编译输出 `dist/preload.cjs`。
2. 将主进程 preload 路径改为 `preload.cjs`，同步更新静态安全测试。
3. 重新执行桌面 typecheck、测试和 electron-builder 打包。
4. 在隔离 `OPENCODEX_HOME` 下启动便携版，确认 runtime-port.json、healthz 和 renderer preload 日志均正常。

## 调试工具

- `Get-Content desktop/out/.../resources/app.asar` 配套 Electron 日志
- `ELECTRON_ENABLE_LOGGING=1`、`ELECTRON_LOG_FILE`
- `Get-Process`、隔离 `C:\\tmp` 用户目录和 `runtime-port.json`

## 注意事项

- preload 只允许固定 lifecycle IPC，不得借此扩大 renderer 权限。
- 真实打包产物必须重新签名并更新 SHA-256，不能沿用旧包记录。
- 每次启动 smoke 使用唯一临时根，结束后按精确路径清理。
