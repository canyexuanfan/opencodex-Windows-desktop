# 上游 v2.22.0 同步合并排查指南

## 问题描述

本 fork 基于 v2.8.0 合并基点，桌面端改造以补丁方式同步过 v2.10.0；上游 lidge-jun/opencodex
已推进到 v2.22.0（约 6280 个非 merge 提交、18 个正式版本）。直接 merge 产生 216 个冲突。

## 已尝试的修复方法及失败原因

- ❌ `git log --oneline f9b9440c..upstream/main` 初次用错比较对象（f9b9440c 是本地的
  upstream/v2.10.0 远程分支引用），应为合并基点 v2.8.0（1adad35）。
- ❌ 首次 `git add docs questions` 失败：仓库启用了 sparse-checkout，`questions/` 不在
  sparse 列表内，需要 `git add --sparse`。
- ❌ 全量 `bun run test` 第一次运行后 Bun 1.3.14 崩溃（internal assertion，exit 3），
  属 Bun 自身 bug（RSS ~1GB / Commit 1.5GB 时），非测试断言失败；需分块或重跑确认。
- ❌ 后台任务通过 grep 管道过滤测试输出，任务被中断时缓冲未刷盘，日志为空；
  改为直接重定向到文件。

## 深层问题分析

- 本 fork 的「同步」历史是补丁式（squash/cherry-pick），git 无法识别同源改动，
  导致冲突面被放大到 216 个文件；后续同步建议改用真 merge 基线（本次已建立）。
- Bun 1.3.14 在 Windows 上跑 803 个测试文件的长套件会内崩，--isolate 模式下内存
  峰值高；分块运行或接受 exit 3 但统计 pass/fail 是当前可行路径。

- 全量测试结果统计（进行中）；若仅 Bun 崩溃无真实失败，记录后继续桌面打包验证。
- 桌面端 electron-builder 打包冒烟：gui 构建 + desktop 打包链路。

- `comm -12 local_only.txt conflicts.txt`（本地真实改动 ∩ 冲突）

- `git add` 需要 `--sparse`；`questions/`、`desktop/` 不在上游 sparse 列表。
- 上游 remote 地址是裸 URL（remote 名缺失时用 `git fetch <url> main:refs/remotes/upstream/main`）。
