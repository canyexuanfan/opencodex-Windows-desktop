---

Codex는 자체 기본 지침, 프로젝트 문서, 권한 및 환경 컨텍스트, 설치된 스킬 등
여러 레이어를 조합해 프롬프트를 만듭니다. **Codex Set → Prompt**에서는 이 구성을
확인하고, 각 레이어가 차지하는 크기를 살펴보고, 원하지 않는 부분을 끌 수 있습니다.

## 목록에 표시되는 정보

각 행에는 조합 순서에서의 위치, 해당하는 경우 이를 제어하는 설정 키, 실제로 보낸
내용의 크기가 표시됩니다.

위치 번호가 연속되지 않는 것은 의도된 동작입니다. 이 숫자는 실제 조합 인덱스이며,
그중 두 개는 아래의 **전환 알림**에 따로 나옵니다. 각 그룹의 번호를 1부터 다시 매기면
Codex가 실제로 쓰지 않는 순서를 보여 주게 됩니다.

### 다섯 가지 레이어 유형

| 유형 | 할 수 있는 작업 |
|---|---|
| 여기서 전환 가능 | 실제 스위치입니다. `config.toml`에 키를 기록합니다. |
| 기능 플래그 적용 | 실제 레이어이지만 이 페이지가 아닌 기능 설정에서 변경합니다. |
| 항상 켜짐 | Codex 어디에도 끄는 스위치가 없습니다. |
| 변경 시 전달 | 전환을 알리므로 무언가 바뀔 때만 나타납니다. |
| 확장 레이어 | 목록에 표시할 수 없습니다. Codex가 공개하지 않습니다. |

끌 수 없는 레이어에는 비활성화된 스위치가 아니라 스위치 자체가 표시되지 않습니다.
회색으로 비활성화된 컨트롤은 기능이 있지만 일시적으로 쓸 수 없다는 인상을 주는데,
실제로는 그런 기능이 없기 때문입니다.

## 레이어 내용 확인하기

레이어 이름을 클릭하면 전송되는 텍스트를 볼 수 있습니다. 대화 상자는
`codex debug prompt-input`에서 내용을 읽으므로 설명문이 아닌 실제 전송 내용입니다.

표시할 내용이 없을 때도 있으며, 대화 상자에 해당하는 이유가 나옵니다.

- **파일은 있지만 비어 있습니다.** `~/.codex/AGENTS.md`가 0바이트라서
  레이어에서 보낼 내용이 없습니다. 대화 상자에 경로가 표시됩니다.
- **확인한 턴에서는 아무것도 보내지 않았습니다.** 레이어는 변경될 때만 다시
  전송되므로, 바뀌지 않은 레이어는 단일 샘플에 나타나지 않습니다.
- **읽을 수 있는 목록 밖에서 전달됩니다.** 기본 프롬프트는 다른 필드로 전송되므로
  여기에는 출력할 수 없습니다.
- **프롬프트를 읽지 못했습니다.** 이 컴퓨터에서 확인 작업이 실패했습니다.

내용은 대시보드가 실행 중인 디렉터리가 아니라 전역 Codex 홈(`~/.codex`)에서
읽습니다.

## 사용자 지정 레이어

**+ Add layer**를 누르면 직접 작성한 지침이 추가됩니다. 사용자 지정 레이어는
`developer_instructions`에 합쳐집니다. 이 키는 내용을 덧붙이는 방식이므로 Codex의
자체 지침은 유지되고 작성한 지침이 추가됩니다.

:::note
의도적으로 `model_instructions_file`을 사용하지 않습니다. 이 키는 기본 프롬프트에
내용을 추가하는 대신 기본 프롬프트를 대체합니다. 따라서 **+**를 이 키에 연결하면
레이어를 처음 저장할 때 Codex의 자체 지침이 삭제됩니다.
:::

사용자 지정 레이어는 그 순서대로 하나의 섹션에 합쳐지므로 사용자 지정 레이어끼리
번호가 매겨집니다. 기본 제공 레이어 사이에 끼어들지는 않습니다.

행의 화살표를 누르거나 행 안의 어느 위치에서든 `Alt` + `Up` / `Alt` + `Down`을 눌러
순서를 바꿀 수 있습니다. 이 순서가 곧 조합 순서입니다.

### 프리셋

**+ Add layer**에는 간결한 출력, 편집 전 계획, 추론 설명, 테스트 우선, 한국어 답변이라는
다섯 가지 시작점이 있습니다. 어느 항목을 선택해도 일반 편집기가 미리 채워진 상태로
열리며 모든 내용을 수정할 수 있습니다. 프리셋은 시작점일 뿐이며, 저장하면 일반 사용자
지정 레이어가 됩니다.

프리셋은 다른 사람의 프롬프트를 복사하지 않고 접근 방식을 간추려 직접 작성한
텍스트입니다. 각 프리셋에는 출처가 표시됩니다.

### 편집 중 레이어 사이 이동하기

편집기에는 이전/다음 컨트롤과 위치 표시기가 있습니다. 이동하는 동안 저장하지 않은
편집 내용이 유지되므로, 편집 도중 두 레이어를 비교하고 돌아와도 입력한 내용이
사라지지 않습니다.

### 호환성 경고

레이어 내용이 작성된 그대로 작동하지 않을 때 편집기에 경고가 표시됩니다. 다른
정체성을 내세우거나, 레지스트리에 정의된 도구 이름을 쓰거나, 아무것도 치환하지 않는
템플릿 자리표시자를 사용하거나, Codex가 나중에 생성하는 환경 정보를 명시하는 경우가
이에 해당합니다.

이 경고는 저장을 막지 않습니다. 의도적으로 Codex 설정을 덮어쓰려는 경우 그대로
진행할 수 있습니다. 경고는 실수가 아니라 의식적인 결정이 되도록 알려 줄 뿐입니다.

## opencodex 밖에서 작성된 지침

`developer_instructions`가 이미 존재하고 opencodex가 작성한 값이 아니라면 패널은 이를
덮어쓰지 않습니다. 대신 텍스트를 레이어로 가져오는 선택지를 제공합니다. 기존 값을
먼저 보여 주며, 확인하기 전에는 아무것도 기록하지 않습니다.

## 동기화가 맞지 않을 때

저장된 레이어와 `config.toml`의 값이 다르면 패널에서 이를 알리고 자동으로 수정하는 대신
**Repair**를 제안합니다. 복구 경로 중 두 가지는 사용자가 작성한 텍스트를 다시 쓰므로
명시적인 선택으로 남겨 둡니다. 레이어 파일이 사라진 경우에는 복구 작업이 변경 전에
백업을 만듭니다.

## 변경 사항이 적용되는 시점

변경 사항은 새로 시작한 세션에 적용됩니다. 이미 실행 중인 세션은 시작할 때의
프롬프트 설정을 유지합니다.

## 이 페이지가 읽는 것과 읽지 않는 것

opencodex가 읽는 설정 파일은 사용자의 `config.toml` 하나입니다. Codex는 여러 레이어에서
설정을 결정하므로, 여기에 표시되는 값은 사용자의 파일에 적힌 값이며 Codex가 최종적으로
계산한 값과 다를 수 있습니다.

## 이 페이지가 쓰는 키

이 키들은 Codex의 `config.toml`에 있으며, opencodex 자체 설정이 아닙니다.

| 키 | 기본값 | 레이어 |
|---|---|---|
| `include_permissions_instructions` | `true` | 권한 |
| `include_collaboration_mode_instructions` | `true` | 협업 모드 |
| `include_environment_context` | `true` | 환경 정보 |
| `include_apps_instructions` | `true` | 앱 |
| `skills.include_instructions` | `true` | 스킬 |
| `developer_instructions` | 미설정 | 커스텀 레이어를 순서대로 이어붙인 값 |

쓰기는 줄 단위 편집이라 주석과 서식이 그대로 남고, opencodex가 모르는 키는 지우지 않고 그대로 둡니다.

키가 없으면 `false`가 아니라 기본값으로 읽습니다. 패널은 파일에 실제로 적힌 값을 보여주고, 키가 설정되지 않은 경우 그렇다고 알려줍니다.
