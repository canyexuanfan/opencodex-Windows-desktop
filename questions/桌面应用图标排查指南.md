# 桌面应用图标排查指南

## 问题描述

桌面端安装包、窗口、任务栏或快捷方式仍显示 Electron 默认图标，用户无法从系统层面识别 OpenCodex。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：桌面端只打包了托盘图标资源，`desktop/package.json` 未配置 Windows 应用图标，Electron 主窗口也未显式传入 `icon`，导致 exe、安装器、桌面快捷方式、任务栏窗口仍可能回退到 Electron 默认图标。

## 深层问题分析

项目已有 OpenCodex 图标资产：

- `src/tray/assets/opencodex-tray.png`
- `src/tray/assets/opencodex-tray-online.ico`
- `src/tray/assets/opencodex-tray-offline.ico`
- `src/tray/assets/opencodex-tray-warning.ico`
- `gui/public/favicon.png`
- `gui/public/logo.png`

托盘图标已经由 `desktop/src/tray.ts` 使用，但 Windows 应用图标需要 electron-builder 的 `win.icon`/NSIS icon 配置；运行时窗口图标需要 `BrowserWindow` 的 `icon` 属性，否则系统 UI 会继续显示 Electron 默认图标。

## 下一步排查策略

1. 使用现有 OpenCodex 图标资产生成 `desktop/build/icon.ico`。
2. 在 `desktop/package.json` 配置 Windows 应用、安装器和卸载器图标。
3. 在 `desktop/src/main.ts` 给 `BrowserWindow` 设置运行时图标，并兼容开发/打包路径。
4. 增加静态契约测试，防止图标配置回归。
5. 重新构建并检查打包输出是否不再提示默认 Electron 图标。

## 调试工具

- `python -c ...` 使用 Pillow 从现有 PNG 生成 ICO。
- `bun test tests/package-static.test.ts`
- `node .\node_modules\electron-builder\cli.js --win nsis portable`
- electron-builder 输出中不应再出现 `default Electron icon is used`。

## 注意事项

- 不引入新的第三方品牌图形，不重新设计 logo。
- 应优先复用仓库已有 OpenCodex 图标资产。
- 图标文件属于产品资产，需要纳入桌面端打包和 git 存档。
