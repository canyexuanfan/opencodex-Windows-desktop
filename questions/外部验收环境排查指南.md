# 外部验收环境排查指南

## 问题描述

桌面端剩余完成项需要 Windows 10/11 干净虚拟机、标准用户/中文用户名、睡眠唤醒、注销重启、受信签名链与跨平台完整回归。当前对话依赖正在运行的真实 Codex，禁止为了验收重启、注销或关闭它；因此先只读确认本机是否已有可隔离使用的 WSL、Hyper-V、Docker 或其他 VM 环境。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-01：默认沙箱执行 `wsl.exe --status` 时，WSL 服务枚举返回 `Wsl/EnumerateDistros/Service/E_ACCESSDENIED`；该结果只能证明沙箱无权限访问 WSL 服务，不能判断宿主机是否安装了发行版。
- ❌ 2026-08-01：默认沙箱执行 `Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All` 需要提升权限，未取得 Hyper-V 启用状态；没有启用、关闭或修改任何 Windows 可选功能。
- ❌ 2026-08-01：一次源码/测试检索把不存在的 `src/config` 与有效的 `src`、`tests` 同时传给 `rg`，有效结果已输出但命令最终返回 1；后续只使用已确认存在的 `src/config.ts`，不重复错误路径。
- ❌ 2026-08-01：只读检查 10100 listener 后未发现占用者，后续命令仍把空 PID 传给 `Get-Process -Id`，触发参数绑定错误；未启动、停止或修改任何进程。后续先判断 PID 非空再查询。
- ❌ 2026-08-01：即使切换到宿主权限，只读 `Get-WindowsOptionalFeature` 查询 Hyper-V 与 Windows Sandbox 仍提示当前用户需要 elevation；没有取得功能状态，也没有请求启用组件。后续不重复 DISM/OptionalFeature 路径，改用普通用户可读的服务状态与现有 WSL 发行版证据判断是否有可直接使用的 VM。

## 深层问题分析

- “程序可在本机隔离启动”不能替代“Windows 10/11 干净 VM 双击可用”，后者必须有不同系统/用户环境的真实证据。
- WSL 只能补充 Linux CLI 回归，不能替代 Windows GUI、睡眠唤醒、注销重启或 Authenticode 信任链验收。
- Docker Linux 容器可补充 CLI/headless 回归，但不能验证 Electron Windows 安装包。
- 当前真实 Codex 会话是不可中断边界；任何系统重启、注销、睡眠或真实 Codex 配置写入都不得自动执行。

## 下一步排查策略

1. 用最小授权只读执行 `wsl.exe --status` 与 `wsl.exe -l -v`，确认是否已有发行版，不安装或启动新系统组件。
2. 只读检查 Docker daemon 与现有镜像；若已有可用 Linux 环境，仅运行隔离 CLI/headless 回归。
3. 若没有现成 Windows VM，则将 Windows 10、标准用户、中文用户名、睡眠/注销/重启与受信证书链明确保留为外部验收，不伪造完成。
4. 当前机器可继续完成静态 UI 可访问性审计、全量测试运行器修复和隔离 Provider 保留回归。

## 调试工具

- `wsl.exe --status`、`wsl.exe -l -v`
- `docker version`、`docker info`
- `Get-WindowsOptionalFeature`（只读但需要提升权限）
- `Get-NetTCPConnection`、`Get-Process`
- 隔离的 `OPENCODEX_HOME`、`CODEX_HOME`、`GROK_HOME` 与 Electron `--user-data-dir`

## 注意事项

- 不执行 `wsl --install`、启用/关闭 Hyper-V、系统重启、注销或睡眠。
- 不启动 Docker Desktop GUI；只在 daemon 已存在时使用只读查询或隔离测试。
- 不读取或修改真实 Codex 配置，不终止真实 Codex/OpenCodex 进程。
- 外部环境缺失不是产品通过证据，未验证项必须继续保持未勾选。
