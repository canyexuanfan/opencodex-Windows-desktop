# 桌面快捷方式缺失排查指南

## 问题描述

用户安装 OpenCodex 桌面端后，发现没有基本的桌面快捷方式。Windows 桌面应用的安装器应至少提供桌面快捷方式和开始菜单入口，避免用户安装完成后找不到程序。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：用户实测安装后没有桌面快捷方式。排查发现 `desktop/package.json` 的 NSIS 配置中 `createDesktopShortcut` 被显式设置为 `false`，而 `createStartMenuShortcut` 为 `true`。这说明不是用户环境或安装器权限导致，而是打包配置主动禁用了桌面快捷方式。
- ❌ 2026-08-02：修复配置后首次执行 `bun run package:resources` 失败，Bun 报 `AccessDenied accessing temporary directory. Please set $BUN_TMPDIR or $BUN_INSTALL`。原因是当前 Codex 沙箱用户访问默认临时目录受限；下一步改用仓库内 `.tmp` 下的精确隔离临时目录设置 `BUN_TMPDIR` 后重试。
- ❌ 2026-08-02：设置仓库内 `BUN_TMPDIR=.tmp\desktop-shortcut-bun-tmp-20260802` 后再次执行 `bun run package:resources` 仍失败，错误相同。说明资源脚本内的生产依赖安装子进程还可能依赖 `TEMP/TMP` 或 `BUN_INSTALL`，不能只设置父进程 `BUN_TMPDIR`。
- ✅ 2026-08-02：同时将 `BUN_TMPDIR`、`TEMP`、`TMP` 和 `BUN_INSTALL` 指向仓库内 `.tmp` 的精确隔离目录后，`bun run package:resources` 成功，资源树生成 4259 个文件。关键经验：当前 Codex 沙箱下 Bun 子进程生产安装需要同时隔离系统临时目录和 Bun 安装目录。
- ❌ 2026-08-02：首次执行 `node .\node_modules\electron-builder\cli.js --win nsis portable` 在构建 NSIS 阶段失败，错误为无法创建 `C:\Users\wzm33\AppData\Local\electron-builder\Cache\nsis-3.0.4.1\...`。原因是当前环境对真实用户 LocalAppData 下 electron-builder 缓存写入受限；下一步改用仓库内隔离 `ELECTRON_BUILDER_CACHE`。
- ❌ 2026-08-02：用户质疑修复后，首次检索生成脚本中的 `RECREATE_DESKTOP_SHORTCUT`/`DO_NOT_CREATE_DESKTOP_SHORTCUT` 时 PowerShell 引号写坏，命令解析失败，未产生有效证据。下一步改用简单 pattern 分次检索。
- ❌ 2026-08-02：改为 `createDesktopShortcut="always"` 后首次资源重包设置了仓库内 `BUN_TMPDIR/TEMP/TMP/BUN_INSTALL`，但 `bun run package:resources` 在 120 秒内未完成，只输出到 `bun install` 开始，不能作为成功证据。下一步先检查残留进程和资源树，再使用更长但有进度证据的构建窗口重试。
- ❌ 2026-08-02：首次准备真实安装器 smoke 时，脚本计划在安装前直接删除当前 Desktop 上的 `OpenCodex.lnk`，被安全审查拒绝。原因是该文件可能是用户真实快捷方式，不能无备份删除。下一步改为若已存在则先移动到唯一备份名，测试结束后恢复；若原先不存在，才在测试结束后删除新建快捷方式。
- ❌ 2026-08-02：改用备份/恢复策略执行真实安装器 smoke 时，当前 Codex 沙箱用户的 `[Environment]::GetFolderPath('Desktop')` 返回空，无法定位代表真实交互桌面的 Desktop 路径。该环境不能作为桌面快捷方式真实落点验收依据，后续不再用沙箱 Desktop smoke 伪造结论，改以 NSIS 生成脚本宏和用户真实安装目视复核作为证据。

## 深层问题分析

桌面端改造时只保留了开始菜单入口，遗漏了普通 Windows 用户对桌面快捷方式的基本预期。该问题属于安装体验功能遗漏，不应交给用户手动创建快捷方式。

## 下一步排查策略

1. 将 `desktop/package.json` 的 `nsis.createDesktopShortcut` 改为 `"always"`，而不是 `true`，确保重装/升级也会补齐桌面快捷方式。
2. 扩展 `desktop/tests/package-static.test.ts`，把桌面快捷方式作为打包契约的一部分。
3. 重新运行桌面打包静态测试、桌面 build，并重新生成安装包。
4. 记录最新安装包 SHA-256，提醒用户需要重新安装/覆盖安装后验证桌面快捷方式。

## 调试工具

- `rg "createDesktopShortcut|createStartMenuShortcut" desktop/package.json desktop/tests`
- `bun test tests/package-static.test.ts`
- `bun run build`
- `electron-builder --win nsis portable`

## 注意事项

- 该修复只改变安装器快捷方式行为，不改运行时代理、Codex 配置或用户数据目录。
- 不用当前对话环境重启 Codex。
- 后续安装器测试必须检查桌面快捷方式、开始菜单入口、卸载后的快捷方式清理。

## 更新记录

- 2026-08-02：创建本指南并记录首次定位结果。
- ❌ 2026-08-02：将 `desktop/package.json` 的 `nsis.createDesktopShortcut` 改为 `true` 后虽然通过静态测试和重包，但用户质疑该修复没有解决实际安装后的快捷方式问题。复查 electron-builder 源码确认 `true` 只对应 `DesktopShortcutCreationPolicy.FRESH_INSTALL`，即主要覆盖全新安装；重装/升级或旧状态下缺少桌面快捷方式时可能不会重建。因此该版本不能算完整修复，必须改为 `"always"`。

- ✅ 2026-08-02：本轮 `"always"` 重包使用的仓库内临时目录已清理：`desktop-shortcut-always-bun-env-20260802`、`desktop-shortcut-always-bun-install-20260802`、`electron-builder-cache-shortcut-always-20260802` 已删除，未发现 `desktop-shortcut-real-smoke-20260802` 残留。
