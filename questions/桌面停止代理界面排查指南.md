# 桌面停止代理界面排查指南

## 问题描述

桌面端点击“停止代理”后，不应整页切换成独立离线页面；用户仍需要看到 Dashboard、侧栏、设置和日志等原有功能入口，只把左下角生命周期按钮从“停止代理”切换为“开启代理”。同时 Windows 上方 Electron 默认菜单栏对普通用户没有价值，应隐藏。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：首次实现把停止成功后的界面交给 `desktop/src/main.ts` 的 `showOfflineState()`，该函数用硬编码 HTML 覆盖当前页面。结果虽然能重新启动代理，但丢失了 Dashboard 主界面、导航和上下文，用户体验像“程序坏了”。
- ❌ 2026-08-02：将按钮 className 先抽成组件内字符串常量后，GUI i18n lint 将 `"theme-toggle stop-toggle"` 误判为硬编码 UI 文案。下一步把 className 保持在 JSX 属性表达式里，沿用项目已有模式。

## 深层问题分析

- 代理停止不等于桌面壳停止。Electron preload 仍可通过 IPC 调用主进程启动代理，因此无需卸载 React 页面或跳转到兜底离线页。
- 手动停止后旧 Dashboard 文档虽然无法再访问旧端口 API，但仍可作为可交互外壳保留；左下角按钮应直接调用 `desktop:start-proxy`，由主进程在新端口 ready 后重新 `loadDashboard(newPort)`。
- 独立离线页只适合“首次启动代理失败且没有 Dashboard 可显示”的兜底场景，不适合正常用户主动停止代理。

## 下一步排查策略

1. 主进程停止成功后不再调用 `showOfflineState()`，只发布 sidecar 状态并保持窗口可见。
2. 通过 preload 暴露受限状态订阅，React 根据 `starting/ready/stopped/failed` 切换按钮文案和禁用状态。
3. Electron 主窗口隐藏默认菜单栏，并用静态测试防止回归。
4. 用 GUI lint/i18n lint、desktop typecheck/build 和静态契约测试验证。

## 注意事项

- 不要为了显示离线状态而覆盖整页 Dashboard。
- 不要让 renderer 获得任意 IPC 通道；preload 只能暴露固定 lifecycle 方法和状态订阅。
- 不要重启或关闭当前用户正在使用的 Codex 会话来测试此问题。
