# 桌面开启代理保留页面排查指南

## 问题描述

桌面端在“提供方”“模型”“日志”等页面停止代理后，再点击“开启代理”，主进程会重新加载新的本地代理端口。但旧实现加载的是 `http://127.0.0.1:<port>/`，没有携带当前页面的 hash 路由，React 因此回退到默认仪表盘，造成用户正在看的页面被硬跳走。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：仅让 GUI 在停止代理后保留 Dashboard 不足以解决开启代理跳页；开启代理成功后 Electron 主进程仍会重新 `loadURL` 到根路径，页面 hash 丢失。

## 深层问题分析

桌面端代理端口是动态端口。切换端口必须重新加载页面 origin，但页面位置由 hash 保存，hash 不会发送给后端，可以安全地附加到新端口 URL。主进程应只从当前本地 Dashboard URL 读取 hash；如果当前不是 `http://127.0.0.1` 页面，则不继承，避免把离线页或外部 URL 的片段带入。

## 下一步排查策略

1. 在 `desktop/src/main.ts` 中从 `mainWindow.webContents.getURL()` 读取当前 hash。
2. 构造新端口 Dashboard URL 时保留 hash。
3. 增加静态测试锁定 `startProxy()` 仍调用 `loadDashboard(status.port)`，但 `loadDashboard` 默认读取并保留 hash。

## 调试工具

- `desktop/tests/lifecycle-static.test.ts`
- Electron `webContents.getURL()`
- GUI hash 路由：`#providers`、`#models`、`#logs`

## 注意事项

- 不要为这个验证重启当前正在使用的 Codex 会话。
- 不要保留非本地 Dashboard URL 的 hash。
- hash 是前端路由状态，不影响后端请求路径。

## 更新记录

- ❌ 2026-08-02：确认开启代理跳页根因是主进程切换端口时丢失当前 hash。
- ✅ 2026-08-02：在 `desktop/src/main.ts` 增加 `currentDashboardHash()` 与 `dashboardUrl(port, hash)`，`loadDashboard()` 默认保留当前本地 Dashboard hash；`desktop/tests/lifecycle-static.test.ts` 增加回归，确认 `startProxy()` 切换端口时不会丢失 `#providers` 等页面路由。定向验证：`cd desktop && bun test tests\lifecycle-static.test.ts` 5/5 通过。
