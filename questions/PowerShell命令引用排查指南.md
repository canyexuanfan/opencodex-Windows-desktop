# PowerShell 命令引用排查指南

## 问题描述

在 Windows PowerShell 中执行验证命令时，复杂正则、中文引号、反引号、括号或多层字符串经常被调用层提前拆分，导致命令没有真正执行预期检查。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：阶段 37 轻量验证中使用一条 `Select-String -Pattern "阶段 37|...|不得把“桌面端改造目标”"` 同时匹配多个中文片段。PowerShell 将包含中文弯引号的片段拆成额外位置参数，报 `找不到接受实际参数“桌面端改造目标”的位置形式参数`。该命令没有产生有效验证证据。

## 深层问题分析

PowerShell 5 对命令行字符串、中文标点和复杂正则的解析比较脆弱；外层工具传参后，实际进入 PowerShell 的字符串不一定与编写时一致。把多个检查合在一条复合正则里，失败时也很难判断是哪一段引号或转义造成的问题。

## 下一步排查策略

1. 优先使用固定字符串逐条匹配，避免在同一条命令里混合多个复杂片段。
2. 对中文弯引号、反引号、`$()`、括号、管道符、正则分组等字符，尽量拆成多条简单命令。
3. 需要复杂解析时，优先用仓库内临时脚本文件执行；不要把长脚本塞进 `node -e` 或 PowerShell 单行字符串。
4. 命令失败后先记录失败，再用更简单的只读命令复核，不把失败命令的输出当成产品失败。

## 调试工具

- `Select-String -SimpleMatch`
- `rg -F`
- `Get-Content -Encoding utf8`
- 临时 `.tmp/*.ps1` 或 `.tmp/*.js` 脚本

## 注意事项

- 不要为了绕过引号问题改业务代码。
- 不要把包含敏感配置或 API Key 的原文输出到日志；需要检查配置时只输出红acted 摘要。
- 验证命令应尽量短、只读、可重复。
