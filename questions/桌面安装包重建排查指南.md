# 桌面安装包重建排查指南

## 问题描述

桌面端收尾需要重新生成资源树与 `OpenCodex-Setup-x64.exe`，但打包命令容易受当前 shell 工作目录、临时目录权限和沙箱边界影响。

## 已尝试的修复方法及失败原因

- ❌ 2026-08-02：在仓库根目录执行 `bun run package:resources`，并把临时目录设为 `C:\tmp\opencodex-resource-stage34-20260802`。
  - 失败原因 1：当前沙箱进程创建该 `C:\tmp` 子目录返回 `UnauthorizedAccessException`。
  - 失败原因 2：`package:resources` 脚本定义在 `desktop/package.json`，仓库根包没有这个脚本。
  - 经验：资源重建应在 `desktop` 工作目录执行 `bun run package:resources`，临时目录优先放到仓库 `.tmp/` 或在需要时使用最小范围授权。
- ❌ 2026-08-02：在 `desktop` 工作目录执行 `bun run package:resources`，并设置 `TEMP/TMP/BUN_TMPDIR` 到仓库 `.tmp/desktop-resource-stage34-20260802`。
  - 失败原因：资源脚本内部的生产依赖安装子进程仍报 `AccessDenied accessing temporary directory`，提示还需要设置 `BUN_INSTALL`。
  - 经验：Bun 资源重建不能只绑定 `BUN_TMPDIR`；要同时绑定 `BUN_INSTALL` 到可写的任务级临时目录。
- ❌ 2026-08-02：补齐 `TEMP/TMP/BUN_TMPDIR/BUN_INSTALL` 后在沙箱内重跑 `desktop/package:resources`。
  - 失败原因：资源脚本进入生产依赖安装后 240 秒未完成，未生成 `desktop/resources/staging/manifest.json`，不能把半成品资源树用于打包。
  - 经验：阶段性打包需要在非沙箱临时目录/缓存中执行，完成后再用 manifest、installer hash 和产物列表复核；半成品 staging 必须被下一次成功资源重建覆盖。
- ✅ 2026-08-02：按最终带版本安装包名重建：使用非沙箱精确临时根 `C:\tmp\opencodex-resource-stage34-versioned-20260802` 执行 `desktop/bun run package:resources`，成功生成 4260 个资源文件；随后使用 `C:\tmp\opencodex-installer-stage34-versioned-20260802` 与本地 electron-builder 只构建 NSIS 安装版。
  - 产物：`desktop/out/OpenCodex-Setup-2.8.0-x64.exe`
  - SHA-256：`368F70370A7BC95B6C1C560EC938629DC91BB8582200EF2FBD893B32B053022D`
  - 复核：`OpenCodex-Setup-x64.exe` 不存在，`OpenCodex-Portable-x64.exe` 不存在。
  - 清理：本轮 stage34 的 `C:\tmp`、`%TEMP%\ocx-update-job-30732-*` 与仓库 `.tmp` 精确临时目录均已清理，复核输出 `STAGE34_TEMP_CLEAN`。

## 深层问题分析

- Windows 桌面打包会同时写入 `desktop/resources/staging`、`desktop/out` 和临时缓存；这些路径必须明确，不能依赖默认 `%TEMP%`。
- shell 工作目录不同会改变可见的 npm/bun 脚本集合；仓库根脚本与桌面包脚本不能混用。

## 下一步排查策略

1. 使用 `desktop` 作为工作目录重跑 `bun run package:resources`。
2. 若临时目录仍被沙箱阻止，改用仓库内 `.tmp/desktop-resource-stage34-20260802`。
3. 同时设置 `TEMP/TMP/BUN_TMPDIR/BUN_INSTALL` 到可写任务目录；若沙箱超时，使用最小范围授权的非沙箱命令。
4. 资源树成功后确认 `desktop/resources/staging/manifest.json` 存在且 fileCount 正常。
5. 执行 `bun run build` 与 `electron-builder --win nsis`，确认只生成安装版。
6. 计算安装包 SHA-256，并确认没有 portable 产物。

## 调试工具

- `bun run package:resources`
- `bun run build`
- `node .\node_modules\electron-builder\cli.js --win nsis`
- `Get-FileHash .\out\OpenCodex-Setup-x64.exe -Algorithm SHA256`
- `Test-Path .\out\OpenCodex-Portable-x64.exe`

## 注意事项

- 不重启当前 Codex 会话。
- 不碰真实用户 Codex 配置。
- 删除临时目录前必须使用精确路径。
